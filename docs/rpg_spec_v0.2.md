# 2D RPG 開発仕様書 v0.2

対象: Godot 4.7 / GDScript / 2D 見下ろし型・ターン制コマンド RPG
用途: Claude Code に渡す開発仕様（`docs/SPEC.md` として配置することを想定）

## 0. この文書について

### 0.1 v0.1 からの主な変更点

- 技術的に未確定だった項目（解像度・タイルサイズ・マップ方式・Autoload・入力・フォント）を**既定値として確定**した。
- ゲームルール（ダメージ式・行動順・逃走・魔法・全滅時・エンカウント詳細）を追加した。
- 会話・イベント・宝箱・ショップが共通で使う**条件／アクション**の仕組みをデータ仕様として定義した。
- **初期データ（数値案）**を追加した。数値はすべて暫定で、`tools/balance_sim` で検証・調整する。
- データ検証ツール、ロジック層の分離、テスト方針を追加した。
- 開発フェーズを調整した（データローダー・イベントフラグ・セーブ対象の `GameState` を前倒し）。各フェーズに**完了条件**を付けた。
- タイトル画面、道具屋、城専用モンスターなど、遊びとして成立させるのに必要な最小限の要素を追加した（追加分には「追加」と明記）。

### 0.2 用語

| 用語 | 意味 |
|---|---|
| ハードコード | 数値・文言・配置などをスクリプト内に直接書くこと。本仕様では原則禁止 |
| データ | `data/` 以下の JSON ファイル |
| ロジック層 | Node に依存しない純粋な計算クラス（`RefCounted`）。ヘッドレスでテスト可能 |
| 既定値 | 本書で決定済みの初期値。変更する場合は `docs/DECISIONS.md` に記録する |

## 1. プロジェクト概要

2D 見下ろし型の RPG を開発する。

プレイヤーは村を拠点に冒険を始め、村人から情報を集め、村の外でモンスターと戦って経験値・ゴールド・装備を得る。最終目的は、村から少し離れた魔王城へ向かい、魔王を倒すこと。

ゲーム本体（エンジン部分）と初期コンテンツを分離し、次の追加がコード変更なしで（または最小限の変更で）行えることを最重要要件とする。

マップ / 村・街 / NPC / 会話・イベント / モンスター / ボス / 武器・防具・アイテム / 魔法 / レベル・経験値テーブル / クエスト / ストーリー

### 1.1 ジャンル・方針

- 2D RPG、見下ろし型、マス移動、ターン制コマンドバトル、シングルプレイヤー
- UI と進行は、クラシックな日本製コマンド RPG の「分かりやすくシンプルな UI」を参考にする
- 特定作品の画像・音声・フォント・キャラクター名・呪文名等は使用しない。**すべてオリジナル**とする

| 項目 | 既定値 |

## 4. アーキテクチャ

### 4.1 Autoload

| 名前 | 役割 |
|---|---|
| `Config` | `data/config/*.json` を読み込み、定数的な設定（タイルサイズ、移動速度、文字送り速度、エンカウント猶予歩数など）を提供する |
| `Db` | 全 JSON データを起動時に読み込み、ID で引ける形で保持する（`Db.monster("slime")` など）。存在しない ID の参照はエラーログを出す |
| `GameState` | プレイヤー・所持品・装備・フラグ・現在地・宝箱開封状態・プレイ時間を保持する**唯一の状態置き場**。シリアライズ／デシリアライズ可能にする |
| `EventBus` | ゲーム全体のシグナル（`map_changed`, `flag_changed`, `battle_ended`, `level_up` など）。UI とロジックの疎結合に使う |
| `Flow` | ゲームモードの切り替えとシーン遷移を管理する（§4.2） |
| `SaveManager` | セーブ・ロード（§13） |
| `AudioManager` | BGM・SE の再生。ID から `data/audio/audio.json` を引く |

### 4.2 ゲームモード

`Flow` が以下のモードを排他的に管理する。入力の受付先はモードで決まる。

| モード | 内容 |
|---|---|
| `TITLE` | タイトル画面（ニューゲーム / つづきから） |
| `EXPLORE` | マップ上の移動・調べる |
| `DIALOGUE` | 会話ウィンドウ表示中（移動不可） |
| `MENU` | メニュー画面（ステータス / どうぐ / そうび / セーブ） |
| `SHOP` | 売買画面 |
| `BATTLE` | 戦闘 |
| `CUTSCENE` | イベント進行中（入力はメッセージ送りのみ） |
| `GAME_OVER` / `ENDING` | 全滅 / クリア演出 |

### 4.3 ロジック層の分離（重要）

次の処理は Node に依存しない `RefCounted` クラスとして `scripts/logic/` に置き、ヘッドレスでテストできるようにする。

- `BattleCalc`（ダメージ・クリティカル・逃走判定・行動順）
- `StatCalc`（基礎値 + 装備 + 修正値の合算）
- `LevelCalc`（経験値からのレベル判定。複数レベル上昇に対応）
- `ConditionEvaluator`（§8.3 の条件評価）
- `EncounterCalc`（エンカウント判定・出現モンスター抽選）
- `SaveSerializer`（`GameState` ⇔ JSON）

乱数は `RandomNumberGenerator` を注入できるようにし、テストでは seed を固定する。

## 5. 入力

InputMap にアクションを定義し、スクリプトにキーを直接書かない。

| アクション | 割り当て |
|---|---|
| `move_up` | W / ↑ |
| `move_down` | S / ↓ |
| `move_left` | A / ← |
| `move_right` | D / → |
| `confirm` | Enter / Z / Space |
| `cancel` | X / Backspace |
| `menu` | Esc / C（探索中は `cancel` でも開く） |

- ゲームパッド（十字キー、A=決定、B=キャンセル、Start=メニュー）は InputMap に定義だけ入れておく（v1 では必須としない）。
- **移動**: 1 マス単位。キーを押し続けると連続して歩く。1 マスの移動時間は `Config` の値（既定 0.15 秒）で、移動中は入力を先行バッファ（次の方向を 1 つ保持）する。
- 斜め移動は不可。同時押しの場合は**最後に押した方向**を優先する。
- 方向キーを押した時、移動不可マスでも**向きだけは変わる**。
- `confirm` で、向いている方向の 1 マス先（NPC・宝箱・セーブポイント）を調べる。

## 6. マップシステム

### 6.1 方式（ハイブリッド）

- **見た目とタイル通行可否**: `TileMapLayer`（Godot 4.3 以降の標準。非推奨の `TileMap` は使わない）を持つシーン `scenes/maps/<map_id>.tscn`。
- **メタ情報**（NPC・遷移・出現テーブル・宝箱・イベントなど）: `data/maps/<map_id>.json`。
- 通行可否は物理コリジョンではなく、**TileSet のカスタムデータレイヤー**で判定する。
  - `walkable: bool`（壁・建物・水・岩・木は false）
  - `encounter: bool`（草地などは true、道・床は false）
- 移動判定は `GridWorld`（占有マス管理）が行う。タイルの `walkable` に加え、NPC・宝箱・動的オブジェクトの占有も考慮する。

### 6.2 マップ JSON

```json
{
  "id": "village",
  "name": "はじまりの村",
  "tilemap_scene": "res://scenes/maps/village.tscn",
  "size": { "w": 30, "h": 22 },
  "bgm": "bgm_village",
  "player_start": { "x": 14, "y": 18, "facing": "up" },
  "respawn": { "x": 14, "y": 17, "facing": "down" },
  "allow_menu_save": true,
  "encounter": { "enabled": false },
  "npcs": [
    { "npc_id": "npc_village_chief", "x": 14, "y": 10, "facing": "down" }
  ],
  "transitions": [
    { "x": 14, "y": 21, "to_map": "field", "to_x": 10, "to_y": 2, "facing": "down" }
  ],
  "chests": [],
  "save_points": [],
  "events": []
}
```

- `transitions` は踏むと別マップへ移動する出入口。移動先の座標と向きを指定する。
- `chests` の例: `{ "id": "chest_01", "x": 5, "y": 7, "contents": { "type": "gold", "amount": 80 } }`
  - `type` は `gold` / `item` / `weapon` / `armor`。`item` 系は `id` と `amount` を持つ。
  - 開封状態は `GameState.opened_chests`（`"<map_id>:<chest_id>"`）に保存する。
- `save_points`: `{ "x": 10, "y": 4 }` を調べるとセーブ画面が開く（そのマップでは常時セーブ可）。
- `allow_menu_save`: メニューの「セーブ」を許可するか。**既定は村のみ true**。それ以外のマップではセーブポイントでのみ保存できる。
- `respawn`: 全滅後の復帰位置（村マップのみ必須）。

## 7. 初期マップ（3 マップ）

### 7.1 `village`（村）

- プレイヤー開始地点、村の出口、中央広場、セーブポイント 1 か所
- 村人 3 人（§8.4）
- 武器屋・防具屋・宿屋・**道具屋（追加）**。各店に店員 NPC を 1 人ずつ置く（村人 3 人とは別枠）
- エンカウントなし

### 7.2 `field`（フィールド）

- 草地（エンカウントあり）と道（なし）、通行不可の木・岩・水
- 村への入口、魔王城への入口（村から少し歩いた位置）
- 宝箱 2〜3 個（ゴールド・やくそう・防具など）
- **エリア区分（追加）**: 村に近い側は弱い敵のみ、奥へ進むほど強い敵が出る（§11.2）

### 7.3 `demon_castle`（魔王城）

- 簡易的な構造（入口 → 数部屋 → 最奥の魔王の間）
- 宝箱 2 個、セーブポイント 1 か所（魔王の間の手前）
- 城専用モンスターが出現する（§11.1）
- 最奥に魔王を配置。撃破でゲームクリア

```
村 → フィールド → 魔王城 → 魔王
```

## 8. NPC・会話・イベント

### 8.1 NPC データ

NPC の**定義**は `data/npcs/<npc_id>.json`、**配置**はマップ JSON 側で行う（同じ NPC を複数マップに置ける）。

```json
{
  "id": "npc_village_chief",
  "name": "村長",
  "sprite": "res://assets/characters/villagers/chief.png",
  "move_pattern": "static",
  "dialogue_rules": [
    { "when": { "flag": "defeated_demon_king" }, "dialogue": "village_chief_cleared" },
    { "dialogue": "village_chief_001" }
  ]
}
```

- `dialogue_rules` は上から評価し、**最初に条件を満たしたもの**の会話を再生する。`when` なしは既定（最後に置く）。
- これにより「魔王討伐後だけ会話が変わる」といった分岐がコード変更なしでできる。
- `move_pattern` は v1 では `static` のみ必須（`random_walk` は将来対応）。

NPC に話しかけると、NPC はプレイヤーの方を向く。

### 8.2 会話データ

`data/dialogues/<dialogue_id>.json`。ノードをつないだグラフ形式とする。

```json
{
  "id": "village_chief_001",
  "start": "n1",
  "nodes": {
    "n1": { "type": "text", "speaker": "村長", "text": "よく来たな、旅の者よ。", "next": "n2" },
    "n2": { "type": "text", "speaker": "村長", "text": "この村の北には魔王城へ続く道がある。", "next": "n3" },
    "n3": { "type": "text", "speaker": "村長", "text": "魔王を倒すには、十分に力をつける必要があるぞ。", "next": "n4" },
    "n4": { "type": "action", "actions": [ { "do": "set_flag", "flag": "met_chief" } ], "next": null }
  }
}
```

ノード種別:

| type | 内容 |
|---|---|
| `text` | 話者名と本文を表示。`confirm` で次へ。`next` が `null` なら終了 |
| `choice` | 選択肢を表示。`choices: [{ "label": "...", "next": "nodeId" }]` |
| `branch` | `if`（§8.3 の条件）が真なら `then`、偽なら `else` のノードへ |
| `action` | §8.5 のアクションを順に実行し、`next` へ |

選択肢＋条件分岐の例（宿屋）:

```json
"n1": { "type": "choice", "speaker": "宿屋の主人", "text": "ひと晩 8ゴールドです。とまりますか？",
        "choices": [ { "label": "とまる", "next": "n2" }, { "label": "やめる", "next": "n9" } ] },
"n2": { "type": "branch", "if": { "gold_gte": 8 }, "then": "n3", "else": "n8" },
"n3": { "type": "action", "actions": [ { "do": "take_gold", "amount": 8 }, { "do": "heal_full" } ], "next": "n4" }
```

- 本文中の `{player_name}` `{gold}` などの変数は、実行時に置換する。
- 会話ウィンドウは**最大 3 行**、1 行の文字数は日本語で全角 18 文字程度を目安に自動折り返しする。文字送り速度は `Config`（既定 30 文字/秒）、`confirm` 長押しで高速化する。

### 8.3 条件（Condition）

会話の `branch`、NPC の `when`、イベント、ショップなど**すべて共通の書式**を使う。`ConditionEvaluator` が評価する。

| キー | 意味 |
|---|---|
| `flag` | そのフラグが true |
| `flag_not` | そのフラグが false（または未設定） |
| `gold_gte` | 所持金が指定値以上 |
| `level_gte` | レベルが指定値以上 |
| `has_item` | そのアイテムを所持 |
| `all` / `any` | 条件の配列。AND / OR |
| `not` | 条件の否定 |

同じオブジェクト内に複数キーを書いた場合は AND とする。

### 8.4 初期 NPC（村人 3 人 + 店員）

| NPC | 役割 | 会話内容 |
|---|---|---|
| 村長 | ゲームの目的 | 村の説明、魔王の存在、魔王城の場所、魔王を倒す目的 |
| 冒険者 | 戦闘の説明 | 戦い方、経験値、レベルアップ、装備の重要性、魔法 |
| 商人 | 買い物の説明 | 武器屋・防具屋・道具屋、お金の入手方法、装備変更 |
| 店員 ×4 | 武器屋 / 防具屋 / 道具屋 / 宿屋 | `open_shop` や宿泊の会話 |

村長と冒険者は、`defeated_demon_king` が true の時に別の会話へ切り替わるように設定する（クリア後対応の確認用）。

### 8.5 アクション（Action）

会話の `action` ノード、イベント、宝箱などが共通で使う。`ActionRunner` が実行する。

| do | パラメータ | 内容 |
|---|---|---|
| `set_flag` | `flag`, `value`（既定 true） | フラグを設定 |
| `give_gold` / `take_gold` | `amount` | ゴールド増減 |
| `give_item` / `take_item` | `item`, `amount` | アイテム増減 |
| `give_weapon` / `give_armor` | `id` | 装備品を入手 |
| `heal_full` | – | HP/MP 全回復 |
| `show_dialogue` | `dialogue` | 会話を再生 |
| `open_shop` | `shop` | ショップを開く |
| `start_battle` | `monster`, `on_win`, `on_lose` | 戦闘開始。勝敗でアクションを実行 |
| `warp` | `map`, `x`, `y`, `facing` | マップ移動 |
| `play_bgm` / `play_se` | `id` | 音の再生 |
| `game_clear` | – | クリア演出へ |

アクションの種類は `ActionRunner` に登録する形式にし、後から `start_quest` などを追加しやすくする。

### 8.6 イベント

`data/events/<event_id>.json`。トリガーと条件を満たしたとき、アクションを実行する。

```json
{
  "id": "evt_demon_king",
  "trigger": { "type": "enter_tile", "map": "demon_castle", "x": 10, "y": 6 },
  "conditions": { "flag_not": "defeated_demon_king" },
  "actions": [
    { "do": "show_dialogue", "dialogue": "demon_king_intro" },
    { "do": "start_battle", "monster": "demon_king",
      "on_win": [
        { "do": "set_flag", "flag": "defeated_demon_king" },
        { "do": "show_dialogue", "dialogue": "demon_king_defeated" },
        { "do": "game_clear" }
      ],
      "on_lose": [ { "do": "game_over" } ] }
  ]
}
```

トリガー種別: `enter_tile`（そのマスに入る）、`interact`（調べる）、`map_enter`（マップ読み込み時）、`battle_end`（戦闘終了時）。


### 9.2 ステータス

保持項目: レベル、経験値、最大 HP / 現在 HP、最大 MP / 現在 MP、攻撃力、防御力、素早さ、所持金、装備武器、装備防具。

- 最終値は `StatCalc` が「**基礎値（レベル表） + 装備 + 修正値**」で算出する。修正値（`StatModifier`）の配列を持てる構造にしておき、将来の装飾品・バフ・状態異常に対応できるようにする。
- 将来追加できる構造にする項目: 魔力、運、属性耐性、状態異常耐性。

### 9.3 レベルテーブル

`data/levels/hero_levels.json`。**各レベルの必要累計経験値とステータスを行ごとに持つ**（成長を行単位で自由に調整できる）。

```json
{
  "id": "hero_levels",
  "levels": [
    { "level": 1, "exp": 0,  "max_hp": 30, "max_mp": 5, "atk": 6,  "def": 3, "speed": 5 },
    { "level": 2, "exp": 10, "max_hp": 38, "max_mp": 7, "atk": 8,  "def": 4, "speed": 5 }
  ]
}
```

- 最終行のレベルが上限。上限到達後は経験値を加算しても上がらない。
- 経験値を得るたびに `LevelCalc` が到達レベルを判定する（**一度に複数レベル上がる場合に対応**）。
- レベルアップ時、最大 HP/MP の上昇分だけ現在 HP/MP も増加する（全回復はしない）。
- 習得魔法は `learnset` に従って自動習得する。
- 初期データは §19 を参照。

## 10. 戦闘システム

### 10.1 コマンド

| コマンド | 内容 |
|---|---|
| たたかう | 通常攻撃 |
| まほう | 習得済みの魔法を選択（MP 消費）。MP 不足の魔法は選択不可（グレー表示） |
| どうぐ | 戦闘中に使用可能なアイテムを選択 |
| にげる | 逃走を試みる |

v0.1 では「たたかう」中心でよいとしていたが、魔法とアイテムは回復手段として魔王戦に必要なため、**4 コマンドすべてを v1 で実装する**。

### 10.2 戦闘の流れ

1. エンカウント → 画面演出 → 「{monster}が あらわれた！」
2. コマンド選択（プレイヤー）。敵の行動は敵データに従って決定する
3. 素早さに基づく行動順で、双方の行動をメッセージとともに順に実行
4. 勝敗判定。決着しなければ 2 へ
5. **勝利**: 経験値とゴールドを加算 → レベルアップ演出 → マップへ復帰
6. **敗北（全滅）**: §10.5

メッセージは 1 つずつ表示し、`confirm` で送る（自動送りオプションは将来拡張）。

### 10.3 計算式（`data/config/battle.json` の値を使用）

| 項目 | 式 |
|---|---|
| 攻撃力 | 基礎攻撃力 + 武器攻撃力（`StatCalc`） |
| 防御力 | 基礎防御力 + 防具防御力（`StatCalc`） |
| 物理ダメージ | `max(min_damage, floor((攻撃力 − 防御力) × R))`。`R` は 1 ± `damage_variance` の乱数 |
| クリティカル | 確率 `crit_rate`（既定 3%）。防御力を無視し `floor(攻撃力 × R)` |
| ミス | 確率 `miss_rate`（既定 3%）でダメージ 0 |
| 魔法ダメージ | `floor(power × R)`（防御無視） |
| 回復量 | `floor(power × R)`（最大 HP を超えない） |
| 固定ダメージ（敵の特殊攻撃） | `power`（乱数なし。防御無視） |
| 行動順 | 各行動者の `素早さ × 乱数(0.8〜1.2)` が大きい順。同値はプレイヤー優先 |
| 逃走成功率 | `clamp(0.5 + (プレイヤー素早さ − 敵素早さ) × 0.03, 0.1, 0.95)`。失敗時はそのターン敵のみ行動 |

- 最低ダメージ（`min_damage`、既定 1）により、ダメージが 0 以下にならない。
- `can_flee: false` の敵（魔王）には逃走できない。「にげられない！」と表示する。
- 敵の行動選択: 敵データの `actions` から重み付き抽選。`every_n_turns` が設定された行動は、該当ターンに優先して実行する。

### 10.4 データ構造上の要件

- 戦闘は敵を**配列で保持**し、N 体と戦える構造にする（v1 で出現するのは 1 体のみ）。
- 状態異常・バフは v1 対象外だが、`StatModifier` と戦闘中の効果リストで将来追加できる余地を残す。

### 10.5 全滅時（`Config` で変更可能）

- 所持金を `defeat_gold_penalty`（既定 50%）減らす
- HP/MP を全回復
- 村マップの `respawn` 位置に戻る
- 「ゆうしゃは ちからつきた…」などのメッセージを表示

### 10.6 戦闘 UI

画面は上から「敵の画像（中央）」「メッセージウィンドウ」「コマンドウィンドウ」「プレイヤー状態ウィンドウ（Lv / HP / MP）」で構成する。

```
┌────────────────────────────────┐
│                                │
│           [スライム]           │
│                                │
├────────────────────────────────┤
│ スライムが あらわれた！        │
├──────────────┬─────────────────┤
│ ▶たたかう    │ ゆうしゃ        │
│  まほう      │ Lv 3            │
│  どうぐ      │ HP 35/40        │
│  にげる      │ MP 10/10        │
└──────────────┴─────────────────┘
```

戦闘メッセージは `data/ui/strings.json` のテンプレート（`{actor}` `{target}` `{damage}` などの置換変数つき）から生成する。

## 11. モンスター・エンカウント

### 11.1 モンスターデータ

`data/monsters/<monster_id>.json`。

```json
{
  "id": "slime",
  "name": "スライム",
  "sprite": "res://assets/characters/monsters/slime.png",
  "max_hp": 8, "atk": 7, "def": 1, "speed": 3,
  "exp": 5, "gold": 3,
  "can_flee": true,
  "actions": [ { "type": "attack", "weight": 100 } ]
}
```

- 特殊行動は `{ "type": "skill", "skill_id": "dark_flame", "every_n_turns": 3 }` のように指定する。スキル定義は `data/skills/<skill_id>.json`（`name`, `type`, `power`, `message`）。
- v0.1 の「出現率」は**マップごとの出現テーブルの重み**で表現する（モンスター側には持たせない）。同じモンスターを別マップに別の重みで出現させるため。
- 必須: スライム / ゴブリン / オオカミ。**追加**: 城専用の 2 種（がいこつへい / ガーゴイル）。魔王は §14。

### 11.2 エンカウント

マップ JSON の `encounter` で設定する。

```json
"encounter": {
  "enabled": true,
  "rate_per_step": 0.06,
  "grace_steps": 5,
  "table": [
    { "monster": "slime",  "weight": 50 },
    { "monster": "goblin", "weight": 35 },
    { "monster": "wolf",   "weight": 15 }
  ],
  "zones": [
    { "rect": { "x": 0, "y": 0, "w": 30, "h": 8 },
      "table": [ { "monster": "slime", "weight": 80 }, { "monster": "goblin", "weight": 20 } ] }
  ]
}
```

- 判定は**1 歩ごと**に行う。ただし、遭遇したマスのタイルの `encounter` が true の場合のみ判定する（道では出ない）。
- 戦闘終了・マップ移動の直後は `grace_steps` 歩の間エンカウントしない（連続遭遇の防止）。
- `zones` は矩形領域ごとに別の出現テーブルを設定する。プレイヤーが領域内にいればその `table` を使い、外なら既定の `table` を使う（村に近いほど弱い敵、という強さの段階づけに使用）。
- `enabled: false` のマップ（村）では判定しない。
- 将来の森・砂漠・洞窟・雪原なども、マップ JSON を追加するだけで異なる出現設定を持てる。

## 12. アイテム・装備・ショップ・宿屋・宝箱

### 12.1 データ

```json
// data/items/herb.json
{ "id": "herb", "name": "やくそう", "price": 6, "description": "HPを 30 かいふくする。",
  "effect": { "type": "heal_hp", "amount": 30 }, "usable_in": ["field", "battle"], "stack_max": 99 }

// data/weapons/copper_sword.json
{ "id": "copper_sword", "name": "どうのつるぎ", "price": 60, "atk": 6, "description": "銅でできた つるぎ。" }

// data/armors/leather_armor.json
{ "id": "leather_armor", "name": "かわのよろい", "price": 45, "def": 3, "description": "かたい 皮の よろい。" }

// data/shops/shop_weapon.json
{ "id": "shop_weapon", "name": "武器屋", "sell_rate": 0.5,
  "stock": [ { "type": "weapon", "id": "copper_sword" }, { "type": "weapon", "id": "iron_sword" } ] }
```

`effect.type` は `heal_hp` / `heal_mp` を v1 で実装する。種類は `ItemEffect` として登録式にし、追加しやすくする。

### 12.2 所持品と装備

- 消耗品は `GameState.items`（ID → 個数、上限 `stack_max`）で管理する。
- 武器・防具は所有リスト（`owned_weapons` / `owned_armors`）で管理し、装備はそこから選ぶ。同じ装備品は 1 つまで所有できる（所有済みなら購入不可「もう もっている」）。
- 装備画面では、変更後の攻撃力・防御力の差分（例: `攻撃力 14 → 20 (+6)`）を表示する。装備変更は即座にステータスへ反映する。

### 12.3 ショップ

- 購入時に `所持金 >= 価格` を確認し、購入後に `所持金 -= 価格` とする。足りなければ「おかねが たりない！」と表示する。
- 武器・防具の購入後は「そうびしますか？」と確認する。
- 売却は v1 対象外。`sell_rate` はデータ上の予約フィールド。

### 12.4 宿屋・回復

- 宿屋の主人に話しかけて宿泊（8 ゴールド）すると、HP/MP が全回復する。料金は会話データで定義する。
- 所持金不足の場合は断る会話に分岐する。

### 12.5 宝箱

- 向いている方向の宝箱を `confirm` で開ける。中身は §6.2 の `contents`。
- 取得メッセージを表示（例: 「ゆうしゃは やくそうを 3こ てにいれた！」）。
- 所持上限を超える場合は開けず、「もちものが いっぱいだ」と表示する。
- 開封済みの宝箱は開いた見た目にする。開封状態はセーブする。

## 13. セーブ・ロード・イベントフラグ

### 13.1 セーブ

- 保存先: `user://saves/slot_1.json`〜`slot_3.json`（3 スロット）。設定は別ファイル `user://settings.cfg`。
- 書き込みは一時ファイルに出力してからリネームする（書き込み途中の破損を防ぐ）。
- `save_version`（整数）を必ず含める。ロード時に古いバージョンは `migrate()` で変換し、未知の新しいバージョンは読み込みを拒否してメッセージを出す。
- 戦闘中・会話中・イベント中は保存できない。
- 保存可能な場所: セーブポイント、および `allow_menu_save: true` のマップのメニュー。

保存内容の例:

```json
{
  "save_version": 1,
  "saved_at": "2026-10-04T12:00:00",
  "playtime_sec": 1234,
  "location": { "map": "field", "x": 10, "y": 5, "facing": "down" },
  "player": {
    "level": 3, "exp": 42, "hp": 42, "mp": 9,
    "gold": 125,
    "weapon": "copper_sword", "armor": "cloth_clothes"
  },
  "items": { "herb": 3 },
  "owned_weapons": ["wood_stick", "copper_sword"],
  "owned_armors": ["cloth_clothes"],
  "flags": { "met_chief": true, "bought_first_weapon": true },
  "opened_chests": ["field:chest_01"]
}
```

### 13.2 イベントフラグ

- `GameState.flags`（`Dictionary[String, Variant]`）に保持し、セーブ対象とする。
- 値は bool または整数。命名は `snake_case`（例: `met_chief`, `bought_first_weapon`, `defeated_goblin`, `defeated_demon_king`）。
- フラグ変更時は `EventBus.flag_changed` を発行する。
- 将来のクエスト・ストーリー拡張は、フラグと §8.3 の条件・§8.5 のアクションを増やすことで対応する。

### 13.3 ロード後の復元

マップ、位置、向き、BGM、宝箱の開封状態、フラグに応じた NPC の見た目を復元する。

## 18. データ検証・テスト・バランス調整

### 18.1 データ検証 `tools/validate_data.gd`

実行: `godot --headless --script tools/validate_data.gd`（エラーがあれば終了コードが 0 以外）

検査内容:

- 全 JSON のパース、必須フィールドの存在、ID の重複
- 参照整合性（マップ → NPC / イベント / モンスター、NPC → 会話、会話の `next` / `then` / `else` の先、ショップ → アイテム、`learnset` → 魔法、イベントのアクション参照 など）
- マップ: 座標がマップサイズ内、遷移先が存在、出現テーブルの重みが正
- レベルテーブル: レベルが連番、経験値が単調増加
- 素材パスの存在（警告）

**データを変更・追加した際は必ず実行する。**

### 18.2 テスト

- ロジック層（§4.3）のユニットテスト: ダメージ計算（seed 固定）、複数レベルアップ、条件評価、セーブの往復、エンカウント抽選。ヘッドレスで実行できること。
- テスト用アドオン（GUT 等）を使う場合は `docs/DECISIONS.md` に記録する。
- スモークテスト: `godot --headless --quit-after 60` でエラーなく起動する。

### 18.3 バランスシミュレーション `tools/balance_sim.gd`

データだけを使って戦闘を多数回シミュレートし、次を出力する。

- レベル × モンスター別の勝率、平均被ダメージ、平均ターン数
- 次のレベルへの上昇・各装備の購入に必要な平均戦闘数
- 魔王戦の勝率（レベル・装備・回復アイテム所持数の条件別）

目安: 適正レベルでの通常戦の勝率は 95% 以上、魔王戦は推奨条件（Lv9〜10 + 鉄装備 + 回復アイテム）で勝率 60〜80% 程度。

## 22. Claude Code 向け運用ルール（`CLAUDE.md` の元）

### 22.1 ハードコード禁止

次を**スクリプトに直接書かない**。必ずデータまたは `Config` から読み込む。

NPC の会話内容／モンスターのステータス／レベルごとの必要経験値・ステータス／武器・防具・アイテムの価格と効果／ショップの商品／マップの配置（NPC・遷移・宝箱）／エンカウント率と出現テーブル／経験値・ゴールド／イベント条件／UI 文言／タイルサイズ・移動速度などの定数／音の対応

### 22.2 コーディング規約

- GDScript は静的型付けを使う。`class_name` を付与し、1 ファイル 1 責務とする。
- 命名: 変数・関数・ファイル名は `snake_case`、クラス名は `PascalCase`、定数は `UPPER_SNAKE_CASE`。
- UI とゲームロジックの連携は `EventBus` のシグナルで行い、直接参照を避ける。
- Godot 4.7 で非推奨の API（`TileMap`、旧形式の `yield`、文字列での `connect` など）を使わない。API に自信がない場合は公式ドキュメントで確認する。
- ロジック層は Node に依存させない（§4.3）。

### 22.3 進め方

- 着手前に `docs/SPEC.md` と `docs/DATA_SCHEMA.md` を読む。
- 1 回の作業はフェーズ 1 つ分にし、完了条件を満たしたらコミットする。
- データの追加・変更後は `validate_data` を実行する。
- 仕様にない判断が必要な場合は、迷った点を質問し、決定した内容を `docs/DECISIONS.md` に記録する。
- 本書の既定値を変更した場合も `docs/DECISIONS.md` に記録し、必要なら本書を更新する。
